# v11_flower: 꽃 탐지와 개화 단계 분류 데이터

**상태: test 검수 완료, 학습 전**. 잎 모델(v8, v9)과 분리해서 관리합니다. 가중치는 아직 없습니다.

## 구조
잎 파이프라인과 같은 2단계입니다.

1. **꽃 찾기:** YOLO 탐지, `flower` 1클래스
2. **단계 분류:** 박스 긴 변 × 1.25 정사각형 크롭 → 봉오리 / 개화중 / 만개

## 폴더
| 경로 | 내용 |
|---|---|
| `labels/annotations.csv` | 라벨 원본. 사진별 박스, 단계, 출처(`legacy`, `draft`) |
| `labels/ignore_regions.csv` | 판단이 어려워 학습에서 가리는 영역 |
| `labels/photos.csv` | 사진 목록, 기기, 구간, 분할, 라벨 상태 |
| `labels/drafts/` | 사진별 라벨 초안 |
| `scripts/` | 초기화, 라벨 작업, 검수 이미지, 내보내기, 묶음 제작 |
| `sheets/review_test/` | test 검수 이미지 |

사진은 `photos/`에 있습니다. 좌표는 EXIF 회전을 적용한 기준입니다. 이 폴더의 `photos/`와 라벨이 기준이고, 로컬 PC의 `v11_flower`는 라벨 작업을 시작한 곳입니다.

`crops/`(기존 크롭), `cube/`(큐브 사진), `data/`(내보낸 학습 데이터)는 서버 폴더에만 두고 Git에 넣지 않습니다.

## 라벨 규칙
사용자가 2026-11-02에 확인한 기준입니다.

- **대상:** 사진 속 모든 꽃. 작은 봉오리, 초록 봉오리, 흰 꽃을 포함합니다.
- **박스:** 꽃받침까지 포함하고 줄기와 잎은 뺍니다. 가려진 꽃은 보이는 부분만 잡습니다. 꽃받침 포함이 더 정확한지는 학습 후 비교합니다.
- **봉오리:** 꽃잎이 닫혀 있음. 위에서 봐서 둥글게 보이는 초록 봉오리도 포함합니다.
- **개화중:** 꽃잎이 풀리기 시작함. 컵 모양이나 나선이 보이고 아직 납작하지 않습니다.
- **만개:** 꽃잎이 활짝 펴짐. 납작하거나 수술이 보입니다.
- **제외 영역:** 사진 가장자리에서 크게 잘린 꽃, 바닥에 떨어진 꽃, 흐리거나 가려져 판단이 어려운 대상
- **꽃자리:** 이 농장 사진에는 없습니다. 둥근 초록 대상은 봉오리로 표시합니다.
- **뺀 것:** 새순
- **뺀 사진:** 온실 전경(`20261030_135013.jpg`). 내부 카메라 시점과 달라 내보내지 않습니다.

## 분할
휴대폰 두 대가 같은 시각에 다른 재배대를 찍어서, 사진이 아니라 시각 구간 단위로 나눴습니다.

| 분할 | 구간 | 사진 |
|---|---|---:|
| test | 13:49:05~13:49:38, 13:50:07~13:50:52, 14:04:19~14:04:40 | 18 (전경 1장 제외) |
| val | 13:46:01~13:46:42 | 8 |
| buffer | test, val과 같은 재배대로 보이는 사진 (어떤 학습과 평가에도 쓰지 않음) | 9 |
| train | 나머지 | 108 |

- test 사진의 박스는 내보낼 때 test로만 가고 학습 데이터에 들어가지 않습니다.
- **화분 단위 분리는 아닙니다.** 같은 품종과 인접 재배대가 train에도 있습니다. 예를 들어 흰 꽃 `134851`, `134857`과 노란 꽃 `134337`, `134355`, `134757`입니다. 그래서 test 점수는 실제보다 높게 나올 수 있습니다.
- 사진은 모두 하루, 한 농장, 휴대폰으로 찍었습니다. 독립 평가는 다른 날 찍은 ESP32 사진이 필요합니다.

## 현재 라벨 (2026-11-03)
| 분할 | 상태 | 봉오리 | 개화중 | 만개 |
|---|---|---:|---:|---:|
| test 17장 | 사용자 검수 완료, 수정 없음 (`verified`) | 424 | 33 | 44 |
| val 8장 | 전체 라벨 초안 | 225 | 22 | 29 |
| train 13장 | 전체 라벨 초안 | 317 | 20 | 11 |
| train 95장 | 기존 박스만 (누락 있음) | 737 | 85 | 57 |

- `legacy`: 2026-10-30에 꽃잎 색 후보를 썸네일로 판정한 라벨. 초록 봉오리, 흰 꽃, 작은 대상이 빠져 있습니다.
- `draft`: Claude가 격자 이미지를 보고 만든 초안. 잎을 봉오리로 잘못 잡았거나 빽빽한 사진에서 작은 봉오리를 놓친 경우가 있을 수 있습니다.
- 탐지 내보내기는 `draft`, `verified` 사진만 씁니다.
- train 초안의 만개가 11개뿐입니다. 탐지는 1클래스라 영향이 작지만, 단계 분류에는 기존 라벨의 크롭도 함께 씁니다.

## 사용 방법
```bash
python scripts/00_init_labels.py          # 사진 목록과 분할 재계산 (라벨은 유지)
python scripts/10_view_photo.py 134908    # 격자 보기 생성
python scripts/11_apply_draft.py 134908   # 초안을 라벨 원본에 반영
python scripts/12_review_sheets.py test   # 검수 이미지 생성
python scripts/20_export.py               # data/det, data/cls 생성
python scripts/30_package.py              # 서버 업로드 묶음 생성
```
Pillow만 있으면 실행됩니다.

## 내보내기
- **탐지:** 1280px 타일(겹침 25%)을 640으로 줄인 것과 사진 전체를 640으로 줄인 것. 잘려서 50% 미만만 보이는 꽃은 회색으로 가립니다.
- **분류:** 박스가 있는 사진의 모든 대상. `data/cls/index.csv`에 분할, 출처, 사진, 기기를 기록합니다.

| 분할 | 탐지 타일 | 대상 | 분류 크롭 |
|---|---:|---:|---:|
| train | 169 | 921 | 1,227 |
| val | 104 | 743 | 276 |
| test | 221 | 1,308 | 501 |

타일은 사진 전체를 줄인 이미지를 포함하고, 한 꽃이 겹친 타일에 중복으로 들어가므로 대상 수는 박스 수보다 많습니다. `data/det/flower.yaml`의 `path`는 만든 PC의 절대 경로이므로, 서버에서는 `20_export.py`를 다시 실행합니다.

## 남은 일

2. 분류 학습, 탐지 1차 학습, 그 예측으로 나머지 train 라벨 후보 생성
